# Design System: Ember

## Scope and character

Ember is a fast workout ledger with its evidence one step away. It is phone-only: the owner never uses it on a computer. The desktop layouts described below (from 1000px) remain in the code and should not be broken deliberately, but new work is designed, tested and verified at phone sizes only. The shipped redesign uses a restrained shadcn component family, warm Paper/Ink and Night neutrals, bundled Inter and one Amber accent. Soft corners, hairline borders and spacing establish hierarchy; the workout controls are gym-specific and thumb-friendly. Generic logging conventions inform the workflow, not Strong's branding or assets.

This is the contract for the real application, not the synthetic approval prototype. The IndexedDB writer, local active draft, immutable outbox, authentication/ownership gates, conflict retention and finite PWA shell remain authoritative. A visual change never substitutes prototype storage or rewrites saved history. Synthetic examples are not production data.

## Palette, type and shape

- `src/index.css` is the only stylesheet and source of the semantic tokens above. `[data-theme='dark']` selects Night. Amber is the only accent: light `#9e5700`, Night `#f5b13d`; `primary-tint` is `#f5ead6` / `#332b1f`, and the focus ring equals primary. No accent picker.
- Primary marks Start, Finish, confirmed checks, navigation and personal-record dots. Secondary is the selected-segment wash with Amber text. Chart series stay neutral (`chart-primary`); past weekly bars use `chart-secondary` with its edge stroke, the current week Amber. Volume is not a strength colour. Body-weight changes carry no good/bad colour.
- Destructive text identifies removal; solid destructive fill is reserved for a confirmation. Cancel workout and undoable Delete entry are outlined destructive-text actions. Storage errors use destructive; do not repurpose the currently unused warning token without checking its distinction from Amber.
- System theme is the default and follows live OS changes. Light/Dark override it. The validated versioned `ember:appearance:v1` preference is separate from workout data; old accent fields are ignored. Failed preference storage keeps the current tab usable and reports the failure, without changing workout-saving claims.
- Inter Variable is bundled locally, with Inter/system-ui/sans-serif fallbacks and `cv11`. No CDN, display font or ornamental monospace. Named styles: page-title 24px/600, section-title 18px/600, card-title 16px/600, label 12px/500, caption 11px, set-value 18px/600, stat 28px/600. Page/stat tracking is −.025em/−.02em. Use weights 400/500/600/700, not 550/650.
- Body copy is 14px/1.5 in muted foreground; input text is at least 16px. Set inputs are centered 18px/600. Button labels are 14px/500; exercise-list names are 14px/500, body parts 12px. Chart axes must render at 11 CSS px or larger. All values, counts and dates used for comparison use tabular numerals.
- Corners are soft: `--radius` 8px, `--card-radius` 12px. Buttons, fields, chips, the status pill, menus, segment groups, reorder rows, exercise thumbnails and tinted notes (inline errors, metric explanations) use `rounded-md` (6px); set checks, inline menu rows and PR tags `rounded-sm` (4px); cards, banners, centred dialogs and the top of drawers `rounded-card` (12px). Full-screen panels and edge-to-edge bands (logger exercise sections, the resume bar, phone action-sheet rows, the tab bar) stay square, as do chart bars. Circular marks (the live dot, switches, chart dots and the drawer handle) stay round. Flat cards have 1px token borders, not decorative shadows. Dialog elevation uses `--shadow` and a 60% Paper / 85% Night scrim.
- The icon is the Ember heart: two amber flame ribbons around a faceted glowing coal, in flat tones on navy `#1F2D3D`. The same mark is the launch splash and finish celebration heart (`EmberHeart`). `public/icons/` holds the full-bleed any/maskable PNGs (glyph inside the 40% safe circle), the iPhone home-screen icon and the tab `favicon.svg`; their glyph layers are the same traced paths as `EmberHeart` and `favicon.svg`, so change the mark in all of them together. The document theme colour follows Paper `#f6f1e8` / Night `#17161b` before first paint; manifest splash/gesture-strip colours stay Night by owner choice because Android does not follow page theme there.

## Shared components and mobile baseline

`src/components/ui/` is the shared primitive layer. Button/Input/Card/EmptyState, SettingsGroup/List/Row, SectionHeading, InlineError and ContentFieldset keep one visual and disabled-state vocabulary. Buttons and set actions are at least 44px; primary drawer actions are at least 48px; menu rows 56px. Focus is a visible 2px primary ring with 2px offset, inset where the control fills its row.

The drawer (vaul), responsive dialog, toggle/toggle-group, chart/ChartTooltip plus chart-touch hook, sonner and skeleton are standard restrained shadcn-style components. Ember's adapters add explicit border tokens, its theme, focus return and preference-aware haptics; the components use the radius tokens above.

- `ResponsiveDialog` uses a vaul bottom drawer below 1000px and the centered Dialog above it. Every confirmation and phone ⋯ menu uses this system, not a native browser confirm. Phone confirmations put the primary action on top, but initially focus the safe choice. Descriptions, Escape, focus trapping/return and scrim dismissal remain part of the contract.
- Responsive drawers include the template preview, workout detail, Previous evidence, metric ⓘ definitions, Body weight form, shell-update confirmation, unreadable-device-state reset, the editors' Discard changes? and logger/template/workout destructive confirmations. Maximum height is constrained by the visible viewport, with contained scrolling and safe-area footer padding. On phones a drawer ends where the on-screen keyboard begins and returns to its own height when the keyboard goes, even if a field keeps focus (`ResponsiveDialogContent` follows `visualViewport` against the layout height; vaul's `repositionInputs` is off).
- Full-screen exceptions are Settings, template editing, History editing, exercise picking, the pushed exercise page and the post-save celebration. They do not become centered cards on phones. Editors ask before discarding a changed draft in a Discard changes? drawer, which is its own back layer.
- Nested surfaces stack. A surface opened from another (History drawer → Edit/Delete, logger or editor → exercise picker, logger → exercise page) leaves its parent mounted underneath, and dismissing it (control, Escape, back gesture) returns to the parent as it was: same scroll and focus on the control that opened it. Full-screen children that cover their parent (editors, the picker, the exercise page) show a ← Back control before the title instead of ✕; partial bottom drawers and confirmations keep ✕ or their Keep button, since the parent shows behind them. Stacked dialogs layer in opening order, each scrim dimming everything beneath it. Source links (an exercise's Charts/History/Records rows, Previous evidence) open the workout drawer over the surface they sit on, and closing it returns to the tapped row. Actions that leave for another place (Repeat, Save as template) close the stack; a menu row closes its menu before its action runs.
- `ActionSheet` is a phone drawer containing menu rows, initially focused on the first action, with arrow/Home/End support. Closing returns focus before handing off an action. Desktop menus retain their inline placement and flip above the trigger if needed; an outside closing tap is consumed, not passed through to a set.
- `SegmentToggle` is an outline ToggleGroup: outline segments with 6px corners, secondary selected wash, Amber selected text, 44px touch targets. Body-part chips and Most done / A–Z use the same typography and selected-state styling; body parts scroll horizontally without widening the page. No selection animation on frequently used filters.
- Toasts use sonner's `Toaster` through `src/components/toasts.tsx`: top center below the safe area on phones (swipe up to dismiss), bottom right on desktop, one visible at a time. App mounts one and hides it while Settings is open, because the modal's focus trap would keep the keyboard from a toast's action; the exercise picker mounts its own below its Back row. Toast buttons are 44px tall.
- No tap highlight/text-size inflation; controls use `touch-action: manipulation`, no selection or iOS callout; input editing remains native. Page overscroll is disabled, internal scrolling contained. Hover states must be capability-gated. Do not truncate comparison values or dates; wrap/reposition metadata before shrinking an action.

## Motion and feedback

Use the established curves: strong ease-out `cubic-bezier(.23,1,.32,1)`, ease-in-out `cubic-bezier(.77,0,.175,1)` for on-screen movement and drawer `cubic-bezier(.32,.72,0,1)`. No `transition: all`, scale-from-zero, sluggish ease-in or hover-only actions. Prefer transform/opacity, and interruptible transitions for repeated state changes. The set tint/check drawing and the deliberate celebration are scoped exceptions using clip-path/stroke and decorative effects.

| Interaction                       | Motion                                                                                                                                                                                            |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Phone exercise page               | Slides from right over 340ms, exits right over 240ms on the drawer curve; retains closing content. Desktop placement does not slide.                                                              |
| Exercise tab underline            | One shared Amber 2px line, sliding by transform over 200ms strong ease-out for pointer activation. Arrow/Home/End navigation moves focus and selection immediately, with no underline transition. |
| Bottom drawer                     | 250ms entry / 180ms exit, drawer curve; dragging remains vaul's native interaction.                                                                                                               |
| Centered responsive dialog        | 180ms fade and scale from 95%; 140ms exit.                                                                                                                                                        |
| Phone logger                      | 420ms up / 300ms down, drawer curve; no motion for a launch-restored draft. Library hides only after coverage.                                                                                    |
| Press                             | Buttons sink to .97 on touch; whole rows/cards to .985, excluding a card's own menu. Keyboard focus does not receive the press transform.                                                         |
| Set confirmation                  | Tint sweeps from check across row over 320ms, wipes out in 140ms; box .86 → 1.08 → 1 over 360ms with a drawn check path. Last checked set adds a drawing badge and one 900ms heading tint flash.  |
| Reorder                           | Other rows shift over 220ms, drop settles over 180ms and briefly tints the dropped card.                                                                                                          |
| Chart inspection / metric changes | Immediate; no series, headline or keyboard animation.                                                                                                                                             |

Reduced motion removes movement, smooth scrolling and transitions, stops the live ping and number rolling, and keeps only the celebration's gentle 200ms fades. No sparks or growing glow under reduced motion. Content and actions must remain usable while optional motion plays.

`src/feedback/` ports the approved prototype's Web Audio synthesis: start, set (an ascending major-pentatonic step per checked set), unset, exercise, finish, pr, delete and tick. Sounds and Haptics have independent Settings switches, both on by default, persisted as validated `ember:feedback:v1` outside workout data. Failed preference writes keep the tab's choice and say so. Turning Sounds on plays the set-check sound; turning Haptics on gives a tick.

Where supported, audio uses an ambient session so music is not paused and the iPhone silent switch is respected. Android haptics use `navigator.vibrate`; iOS 18+ uses the hidden checkbox-switch label tick on touch devices. Unsupported or denied feedback never throws or blocks logging. Do not promise on-device behaviour proven only in Chromium.

Only accomplishments make a sound: start, set, exercise, finish and pr, each with a haptic. Everything else is haptic-only or silent. Explicit checks cue set, the exercise's final check cues exercise 160ms later. Starting an empty/template/repeated workout cues start after any replacement approval. Unticking (unset), Add set and adding an exercise (tick), and set/exercise removal and discard (delete) only buzz. Gestures (chart inspection per selected point, a swipe reaching delete, a reorder lift and each slot it passes) buzz through the same preference-aware path. Navigation is silent: opening menus, cards, rows, tabs, filters, sort, segments, the Finish confirmation and Done. Keystrokes and completion cleared by editing are silent too.

Sounds are mixed to carry over music at the same phone volume (streaming plays near -14 LUFS): a set check near -20 LUFS momentary, start, exercise and PR near -18, finish near -15. The master ends in a -3 dBFS limiter (Web Audio adds a small fixed makeup gain, already in the measurements) that only catches stacked peaks. Re-measure with `node scripts/feedback-levels.mjs` after changing any voice or level.

## Workout ledger

Each exercise heading combines a drawing/name/details target, completion status and a separate 44px ⋯ menu. A finished exercise shows a 16px Amber check badge on its drawing's corner and a plain "Done" status, with no second check. Set columns remain Set / Previous / kg (or Assist. kg / Seconds) / Reps (or km) / Done. The grid is `44px minmax(66px,1fr) minmax(52px,.86fr) minmax(48px,.78fr) 48px`, 6px gaps, at least 56px rows; below 350px gaps reduce to 4px and side padding to 12px. Exercise padding is 20px 16px 18px, 22px 24px in the desktop logger. Completion's target is 44×44px with a 30px visible empty marker; checked rows use a tint that runs edge to edge across the card's side padding (columns stay in place) and lose field chrome.

- Prefilled values are editable targets, never completed sets. Start uses latest eligible matching name/type history for routine/addition targets, repeating the last target if necessary; no matching evidence means blanks. History Repeat copies that exact workout. Duration, cardio, assistance and bodyweight retain their own units and validity rules.
- Focus dims a value without selecting text; the first digit replaces it, preserving native caret editing/Backspace and avoiding the phone's selection toolbar. Weight Enter advances to reps; reps Enter confirms a valid unchecked set and blurs; duration/cardio keep their appropriate Enter path. Edits clear completion. Blank/invalid sets cannot be completed or saved by Finish.
- Previous shows the latest matching session's actual set and date. Its drawer follows the workout drawer's header (exercise name, "Set N · recorded sets only, nothing estimated") and the exercise History/Records vocabulary: label-style section headings; Best at the entered weight as a full-width 56px source row (set value in set-value type, date · workout beneath, ↗); when none match, say so and show Nearest recorded lighter/heavier actual sets (Less/More assistance where applicable) as tagged source rows, never a converted equivalent; Previous session as a date-first source header over its numbered sets, the current set marked with a primary-tint row, Amber number and "This set". Source rows open the workout drawer over Previous; editors show the same rows without links.
- Add/Replace use the shared full-screen catalog/recorded-exercise picker, search, horizontal body-part filters and Recent/All rows. The header names the Add destination or exact Replace source, with no instruction line. Title/Back and search/filters stay above contained results; the phone panel follows the visual viewport, with long context scrolling separately on short screens. Selecting an existing name adds/replaces then closes; Back/Escape/back gesture changes nothing. Already-present rows say “Already in workout/template” before selection; tapping one shows a short error toast saying why, without changing the query. Changing filters returns results to the top. Imported repeated blocks remain distinct. No custom creation or type selector.
- A left swipe reveals explicit Delete, never completes/deletes merely by dragging. Preserve `pan-y`, pointer identity/cancel, containment for portaled events and post-swipe click suppression. The set-number action is the accessible alternative (phone ActionSheet, desktop row reveal). Deletion has no alert/undo banner and preserves survivors; no permanent trash column.
- Hold a heading or its ⋯ 400ms to reorder; a tap on ⋯ still opens its menu. A compact 56px-row list lifts under the finger, auto-scrolls near edges and uses slot ticks. Release keeps exercise identity/sets/checks; Escape/cancel/refused edits restore order. Each ⋯ also provides Move up/down with a polite position announcement portaled outside the logger/editor. Never put a live region inside a modal-covered logger.
- Replace an existing draft, discard and Finish require explicit confirmation. Finish explains completed/unchecked counts and calls the real atomic transaction. Errors keep the draft and stay visible; success opens only after commit. Active workouts never sync to the server.

## Workout, History and shared exercise rows

Workout opens with Quick start / Start empty workout, then Templates and a 44px Create template action. Cards use flat bordered card surfaces, 12px spacing, two columns on desktop and one beside an open logger. Template rows show the prescription that Start will actually prefill via `routineTargets`, not stale template values. Cards include exercise count, an estimated duration derived from known historical minutes per set (rounded to five, omitted without evidence), and last-done wording. Up to four exercises and “+ N more” preview the template. Opening shows all rows and Start workout; ⋯ opens Edit/Delete, and Delete confirms while preserving history.

Template creation and editing use `EditorPanel`, built from the logger's pieces: full-screen on phones, a 680px-bounded desktop side panel, one contained body scroller and no footer. Its header is the logger's: the dismiss control at left (✕, or ← Back when opened from another surface), a centred muted label (New template, Edit template, Edit workout) where the clock sits, and the Amber Save where Finish sits, so Save stays visible with the keyboard open. Below it come the logger's large title field (the name) and its meta line (exercise and set counts), then the same full-bleed exercise cards with drawings, set rows (the set number opens Delete set), ⋯ menu, Add set and Add exercise. Editors drop only the logger's Done column, so kg and Reps sit exactly where they do while logging; Previous stays as evidence, and the card subtitle names the load convention, else the body part. Blank targets remain valid template prescriptions. The phone panel follows visual-viewport height and offset during keyboard resize/pan. Save is always the Amber primary: with nothing changed it just closes an existing item; while saving it reads Saving… and edits and dismissal are locked; a failure keeps the editor, Save reads Retry and an inline destructive strip under the header holds the message and focus (never also a toast). A template needs a name and an exercise: Save underlines the empty name red with "Enter a template name." in the meta line and focuses it, and puts "Add an exercise." under Add exercise; both clear as they are fixed. ✕/←, Escape and back on a changed draft open the Discard changes? confirmation (drawer on phones: Discard changes on top, Keep editing focused); Keep editing, Escape or back return to the last field. Success closes and returns focus to its entry point; the saved template's card gets a brief Amber border instead of a toast.

`ExerciseLine` is shared by template/history cards and previews and the finish screen: 40px drawing, two-line 14px/500 name with safe word breaking, body part in muted 12px, then right-aligned tabular actual/prescribed values. Do not infer a best set from a formula:

- Finished work shows its actual top set: heaviest weight, then most reps at that weight, with set count beneath. Units remain explicit: `75 kg × 8`, bodyweight `12 reps`, holds `60 s`, cardio `1.2 km · 5:00`, assistance `−20 kg × 8` announced as assistance. Amber Trophy means a record set in that workout.
- Templates show a shared load over paired reps (`72.5 kg` / `3 × 8 reps`), bodyweight label over reps, or varied-load top target set over count; blank targets show count only. Never pair an independent weight range with an unrelated reps list.

History groups newest-first cards under sticky month labels, flush with the internal scroller edge on solid background, with matching workout count at right. Cards have a 36px weekday/day column, two-line workout title and compact icon stats: known duration, recorded weighted volume when positive, records set at that time. Under a hairline are up to five ExerciseLines and “+ N more”; below 350px these span the full card. The whole card is one accessible button with a card-level focus ring. Show 20 initially, then Show older workouts adds 20. A just-finished card has an Amber border.

History's title search action reveals a focused inline field on phones and desktop, filtering results as you type. The tabs stay available during search; closing search, Escape or phone back clears it. Search matches names, exercises, dates and months; opening search starts empty. Empty/no-match states say what happened without hiding the query.

The workout drawer shows full date/time, duration/sets/volume/PR stats, every exercise and set, each record kind, and a formula-labelled Epley column only for weighted sets of 1–10 reps. Repeated blocks stay distinct. A pinned footer holds Repeat, Save as template and ⋯ Edit/Delete; Repeat gets its own row on narrow phones. Opening Edit transfers focus to the history editor's title. It slides in over the drawer from the right and shares template editing's `EditorPanel` (← Back, Save, discard confirmation, keyboard-aware body). The meta line adds the weekday and date; native local Start and Duration (min inside the field) sit side by side above the cards. Previous shows the session before this workout, never the workout itself or a later one, and source links are left out while editing. Edits are marked: a changed value gets an Amber field edge, an added set an Amber set number, and the card subtitle adds "1 changed, 1 added", showing what Save would write and Discard would lose. Save with a blocking problem (an unfilled new or changed set, a bad start or duration) shows it in the inline strip and focuses it; a missing name is underlined like a template's. A failed save reads Retry with the retry/reopen message, without dropping the draft. Expected revisions, retained original import cells, conflicts and repeated blocks remain intact; the editor never silently overwrites peers. Back, Cancel or a save returns to the drawer (showing the saved workout) and focuses its ⋯. Delete opens its confirmation over the drawer: Keep returns there; a delete closes both onto the list.

## Exercises and inspectable analytics

Exercises combines catalog and exact recorded names without fuzzy merging: search, body-part chips and one list in the remembered Most done / A–Z sort (Most done by default); only the picker adds a Recent section. Only body parts with exercises appear. Browsing and picking share filtered “N of total exercises” counts and a Clear filter action ("Clear filters" when a search and a body part are both set) that resets search/body part and focuses search without changing the browsing sort. On the Exercises tab it sits at the right end of the Most done / A–Z row under the chips; the picker, which has no sort, keeps it beside the chips. Picker All rows remain A–Z regardless of the saved browsing preference; Recent retains recency order. Rows are at least 64px, pressable, with drawing, two-line name and body part, and an unshrinking right-hand 16px/600 Amber unique-workout count (absent when zero, announced as “Performed in N workouts”). A repeated block counts once for this list/header, not once in its analytics.

Details order is **Charts / History / Records / About**. Charts is initially selected with history, otherwise About. The header contains Back, drawing, full wrapping name, body part and workout count. The tablist has the shared sliding underline and roving arrow/Home/End keyboard navigation. Phone details layer over the still-mounted list or logger; desktop inline details hide the mounted list without clearing its query, body-part filter or sort. Back restores the original row focus and list scroll. Source rows open the workout drawer over the details, from the Exercises tab or the logger alike. Details receive only finished/imported history.

About groups the available drawings, exercise facts (body part/equipment) and muscles into restrained sections, with a bounded drawing pair and an explicit missing-drawing state. It shows no instruction or credit text. Custom names retain history/charts/records with an explicit not-in-catalog state. Catalog metadata retains source, author, adaptation and license URLs. AI-assisted Ember drawings stay marked as such in the data, never attributed to Everkinetic/wger; restore a credits view before any public release. Never silently merge variants or drop repeated sets.

- Weighted chart default: Heaviest weight; alternatives Best reps, Volume and Est. 1RM (Epley). Assistance: Least assistance and Best reps, no resistance estimate. Bodyweight: Best reps. Duration/distance trends remain unimplemented, with a clear empty state.
- Range segments: 1M / 3M / 6M / 1Y / All, full width under the chart. It opens on 3M, widened to 6M, 1Y, then All until at least two sessions fall inside, so a lapsed exercise still draws a line. `TrendArea` uses ChartContainer/ChartTooltip, Recharts, calendar-month ticks, a padded round y-domain and readable 11px labels. Distinct real tick values must remain distinct after formatting.
- Headline is latest value plus change from the first in range, success-coloured when better (less assistance is better). Hover/hold-slide/keyboard inspection shows the selected point's date/value and winning actual set. Volume identifies its heaviest source set, not a fabricated combined set. Duplicate timestamps retain point identity and the matching active marker.
- Every session has a dot; strict improvements over prior workouts get Amber PR dots, not ties or the first workout. PR computation precedes range filtering. Series are neutral, active dot Amber, cursor dashed. Do not animate chart series or headline changes.
- Definitions stay off the page: an ⓘ at the end of the metric row opens an `InfoButton` drawer naming the metric, PR and hold-and-slide inspection. No permanent notes or disclaimers under the chart.
- A newest-first Sessions list (card-title-weight heading with its count) is the exact-value/source alternative: date over workout name at left; at right the trophy and exact metric value over what the value doesn't already say (reps for Heaviest weight, the actual set otherwise, nothing when it would repeat the value) and a chevron; minimum 56px, ten rows then Show more sessions, no nested scroller. Volume reads in kg like History. Values never truncate. Empty/one-session states are explicit, no fabricated line.
- History keeps every exercise block separate as a card: date (card title), workout name · set count, the records that workout set for this exercise in Amber on one line, with short names (Weight · Volume · Est. 1RM; full names for screen readers) (first block of a workout only), then the workout drawer's own `RecordedSets` table (Set / Weight × reps / Est. 1RM). The whole card opens the source workout (a stretched 44px chevron button with a card-level focus ring). Show ten blocks initially, then twenty more per action; one muted line under the list names the Epley column.
- Records has four sections under 14px/600 headings: Best sets (Heaviest weight or Least assistance as the actual set, then Most reps), Heaviest weight for each rep count (compact 48px rows: reps · weight · date), Volume (weight × reps) (Best set, Best session, in kg) and Estimated (Est. 1RM (Epley), with its formula behind an ⓘ). Record rows read label, value in set-value type, then "from <actual set> · date · workout" when the value is computed; every row opens its source workout, and ties keep the domain's original winner. Epley stays limited to weighted sets of 1–10 reps (one rep uses actual load); never apply it to assistance, bodyweight or timed work.

Profile has one muted totals line (workouts · sets · since Mon YYYY), not stat tiles, then Every week, New records, Body parts and Body weight. Every week: the h2, full-width Workouts / Volume / Time segments, the headline, the chart, a right-aligned usual / so far legend and full-width 3M / 6M / 1Y range segments (13, 26 or 52 local Monday weeks; DST-safe local dates). The headline is the last full week ("Last week, 2 – 8 Nov"), or the running week while all history is in it, with "usual X": the median of the full weeks before it in range, counted from the first workout's week and hidden below two such weeks. Time reads as hours and minutes. Inspection changes the headline week, never the usual value. Bars are square and neutral; the headline week is Amber, the running week hatched ("so far"), the usual a dashed foreground line, and a zero week since history began a 2px sliver (none before it). Month ticks label the first week of each month (every other month at 1Y). Its accessible summary lists every exact weekly value. Below, Weeks (count at right) is the exact-value list, newest first from the first workout's week: the week span ("· so far" for the running week), the other two metrics muted and the selected metric at right; a week with workouts expands to 44px weekday · name · duration rows that open the workout drawer in place, returning focus to the row. Four weeks show, then Show all N weeks. New records (Last 4 weeks): one 64px row per exercise, newest first, from `recentRecords` (each workout's records at the time, the lead kind in actual-before-estimate order, gain in success colour over the best that the window's first record beat); a row opens that exercise's page on Records over Profile (← Back to profile, phone back closes it, focus returns to the row). Four show, then Show all N records; no card without records. Body parts (Sets, last 4 weeks, with ⓘ): recorded sets per catalog body part (unlisted names are Other) over the last 28 days, a neutral bar with a foreground tick at the usual (median of the six 28-day blocks before, among blocks with training; hidden below two) and "N / usual"; a row opens Exercises filtered to that body part. No card without sets in the last 4 weeks. Volume is recorded weighted load × reps, time known workout minutes only. Neither volume nor different machine loads establish comparable strength/hypertrophy; nothing on Profile judges a value good or bad.

## Finish celebration

Only a successful finished-workout commit opens the full-screen “Workout complete” dialog over History. The heart-and-flame lights once (Amber gradient, subtle overshoot, radial glow, twelve rising sparks); content rises in a short stagger. Then workout name/date, Duration / Sets / Volume (NumberFlow count-up; units wrap on narrow screens), New personal records when earned, and every exercise as an ExerciseLine. Short landscape reduces the heart; the content scrolls and Done stays pinned.

Records use the same domain definitions as Records against earlier history: heaviest weight, session volume, bounded Epley estimate for weighted work; reps for bodyweight. No first-session record, ties, assisted/timed records, streaks or milestone counts. One row per exercise names every record kind, its headline value and gain; record rows play pr as they arrive, finish plays on open and Done ticks. Reduced motion keeps fades only. ## Save and connection states

Events get toasts, conditions stay on the page. Toasts are few and never block:

- No toast when the screen already shows the result: confirmed deletes, saved edits (a workout or template editor; a saved template's card gets a brief Amber border instead), new templates, Finish, starting a workout, set changes.
- An action with an existing Undo path gets a neutral toast with Undo for about 5s (body-weight delete). A failed restore becomes a Retry toast.
- A result that lands off-screen gets a success toast for about 3.5s (Save as template, which opens the Workout tab).
- A failed one-off action gets an error toast with Retry and Dismiss that stays until used or swiped (template save; body-weight Undo). A refused tap with nothing to retry (picking an exercise already in the workout) gets an error toast that closes after about 3.5s. Other errors inside an open dialog or editor (validation, failed saves) stay inline there and are not repeated as toasts.
- While a workout is running only failures toast; body weight's Undo still shows, since it is that delete's only undo, and Save as template still confirms on a phone while the logger is open, because the logger covers the Workout tab where the new card would show.
- Ongoing conditions (connection and download state, read-only tab, unsaved or unreadable data, sync issues) stay on the page in the three tiers below. Sonner's live region announces toasts.

Conditions come in three tiers (`src/components/Conditions.tsx`). Each condition shows in exactly one place, the open logger or editor, otherwise the page (Settings while it is open), and opens one details drawer (a ResponsiveDialog) with the explanation, the affected items where known, the action where one exists, and Close. Nothing shows when all is well; healthy background sync and brief pending work stay quiet.

- Quiet, heals by itself: Connecting…, Offline (· N waiting with the real pending count) and Downloading history. A small outlined 28px pill (44px target) at the right of the logger's `workout-meta` line, the editors' `editor-meta` line, or beside the page or Settings title. Reconnection is automatic, so the drawer has no Retry.
- Needs you: the read-only tab. A neutral full-width strip (`bg-accent`) with a lock icon and "Reload"; the drawer holds Reload to enable editing. Unsupported Web Locks gives browser guidance with "Details", not a reload that cannot fix it.
- Problem: Changes not synced, Can't save on this phone, Saved data can't be read. A tinted destructive strip (`bg-destructive-foreground`, the editors' failure-strip colours) with "Details". Not-synced details list each held-back change by name with its reason and no resolve action (conflict UX is still open); unreadable data holds Reset unreadable saved data, behind its own confirmation.

Pills and strips sit in the layout, never over it: strips go under the logger or editor header, or pinned above the page under the status bar (under the app bar on desktop) while the title scrolls, so logging, editing and Finish/Save stay reachable. A partial history download is also labelled at the end of the History list ("Older workouts are still downloading", or "Your workouts are still downloading" before any arrive), never shown as an empty history. A sync lock stays a full page ("Connecting…"/"Connection required"); revoked trust keeps owned content and its portals unmounted, and Settings remains reachable. Launch shows only the Ember heart, centered on the page ground, lighting up and growing slightly over 3s after a 400ms delay (so a quick launch shows nothing), until the app opens; a failed connection, a condition or 5s without an answer hands over to the locked page. Reduced motion keeps the delayed fade only.

The logger autosaves without a header notice; a failed save surfaces through its error state. Finish keeps its confirmation open and disables submission/dismissal during saving; failure stays in that dialog and success celebrates only after the atomic commit. Global failed-save guidance is not repeated beside the owning editor's error (an editor with its own failed save omits the Can't save strip). Pill, strip and notice live text is portaled outside the logger/editor and announced only while its visual surface is accessible (problems and the read-only tab assertively, quiet conditions politely); covered background surfaces do not repeat modal feedback. Exercise completion is an inspectable labelled group, not an always-live ancestor inside the logger.

## Settings, Profile body weight and shell updates

On phones the Settings entry is the cog at Profile's top right, outside the disabled content fieldset so read-only/maintenance states can open it. Desktop keeps its header gear; logger and locked states keep their own gears. No Profile Settings row. Closing restores the entry trigger.

Settings uses SettingsGroup sections 40px apart: Appearance (three 48px System/Light/Dark choices; selected 2px Amber ring on card), Feedback (two 64px full-row switches), Notification (one full-row Active workout switch whose line says honestly when the phone has not allowed or has blocked it, an Allow notifications row while permission is still unasked, and only a short Add to Home Screen or not-available line where the browser cannot notify) and App update when available. Notices/retained sync issues are readable inside it. Manual sync, import, JSON Backup & Recovery and in-app data-cleanup controls are not Settings features; underlying recovery/backup capabilities remain intact. Owned history unmounts while sync is locked, including portaled forms.

Body weight is the last Profile section, built like Every week: a card headed by the h2 title and Add weight, holding the chart (or the unframed empty state), with the entry list below the card. It is separate from workout load; the screen does not say so. It unmounts while sync is locked or saved data is unreadable. Add weight/newest-first entries open the responsive form (Add body weight / Edit body weight; drawer on phones), returning to Add weight on close. Add weight focuses kg; an existing entry opens without the keyboard so Delete entry stays in view. The Weight field uses set-value type with a muted kg suffix inside it. Kg accepts comma/point, above 0 through 500, at most two decimals. Date/time defaults to now and supports backdating, stacked below kg on phones. On phones the actions stack 48px high, Save entry on top, then Cancel, then the outlined destructive Delete entry when editing. Save/Cancel and undoable Delete retain validation, revision conflict messages and the existing local transaction/sync semantics. Cancel/back writes nothing. Inputs and submit reflect disabled/saving state even outside the parent's fieldset. Delete shows an Undo toast for that one deletion; it ends when the toast closes, another edit starts or Profile is left.

The chart card follows the exercise Charts: a stat headline with the latest kg (or the inspected entry's, with its date · time), the change since the range's first entry in foreground text (never success/failure colour), the shared `TrendArea` with a neutral line, then the 1M / 3M / 6M / 1Y / All range (default All) when there are two or more entries. The range narrows the chart and the entry list together. None: one explicit empty state and no chart; one entry in range: its value and date with an honest one-entry note, no line. The newest-first entry list (56px rows: date · time, kg, chevron) is the exact-value alternative. Read-only tabs see entries but cannot edit; untrusted installations see no owned history.

App update appears only with a waiting production shell. Apply shell update opens the responsive explicit confirmation, not a browser confirm. Applying requires the existing saved, draft-free, trusted installation-lock transition, including cross-tab checks. Cancel changes nothing. Applying never reloads the current page; the owner closes all tabs and reopens later. The unreadable-device-data reset also requires an explicit responsive confirmation and retains the original bytes; it is never a server-history reset.

## Back, safety and verification

Every transient layer holds one same-document back entry: picker/details, drawer/menu, Settings, editors, celebration and the expanded phone logger. Back closes only the newest; dirty history edits ask and preserve the changes. Main tabs add no history. Chrome can skip entries added without user activation: preserve `src/state/back.ts`'s forward-onto-existing-entry strategy rather than pushing again after a refused back; a prompt the refusal opens shares its layer's entry. A launch-restored logger arms on the first tap.

Hook classes (`app-shell`, `library-scroll`, `settings-panel`, `dialog-content`, `exercise-detail-panel`, `workout-sheet`, `set-row`, etc.) are test/viewport contracts; keep them. No live region inside a covered logger/editor. Portaled owned data must unmount on sync lock, not merely hide under main. Preference persistence is not workout saving; saved means the IndexedDB transaction committed, not a cosmetic timer. Sync is not off-device recovery.

Verify the populated app at Pixel 6 (412×915), 320px and short landscape, in Paper/Night. Stress long/unbreakable/non-Latin names, four-digit counts/loads, many sets, empty/one/large histories and enlarged text. Measure overflow, reachable 44px actions and chart labels, then inspect screenshots. Use synthetic data only and abort API writes in live checks. Chromium touch/viewport emulation does not satisfy real Android/iPhone keyboard, gesture, audio or haptic acceptance; those remain release gates in PRODUCT.md.
