# Design System: Ember

## Overview

The owner-approved redesign is an **Operate** surface: a fast editable set ledger, with the library and evidence one step away. It uses a warm Paper/Ink and Night neutral family with Amber as its only accent, Tailwind v4 theme tokens in `src/index.css`, bundled Inter and square controls. Generic Strong logging conventions inform the workflow; no Strong branding or assets are reproduced.

This document describes the implemented React app (`src/App.tsx`, `src/index.css` and its views/components), not the standalone approval prototype. The real IndexedDB writer, immutable outbox, API authentication, recovery and finite PWA shell remain authoritative. There is no data/schema migration or prototype-storage substitution in this redesign. Synthetic development examples are not production history.

## Colors

- Paper/Ink and Night use the neutral tokens above (`background`, `foreground`, `card`, `muted`, `muted-foreground`, `border`, `accent`), defined in `src/index.css`; Night applies under `[data-theme='dark']`.
- **Amber is the only accent**: light `#9e5700`, Night `#f5b13d`. It is the glow of an ember: gold in the icon and on Night, darkened to bronze on Paper so it reads as text. `primary-foreground` is Paper on light and Night on dark; `primary-tint` is `#f5ead6` / `#332b1f`; `ring` equals `primary`. `secondary` is the selected-segment wash of `SegmentToggle`, with Amber text. There is no accent picker, and no Ocean or Copper.
- Primary carries Start, Finish, confirmed checks, current navigation and links, plus the current week in the Profile chart. The resume bar is not an Amber fill: it is a `card` strip with a 3px Amber inset edge and an Amber chevron. Tint marks completed rows; the selected appearance choice is a 2px Amber ring on a `card` ground, not a tint fill. Metric explanations use foreground text on the `accent` wash. No component uses `warning` yet; its light value sits next to the amber primary, so pick a distinct hue before using it. `destructive` identifies destructive controls and storage/recovery errors; `warning`, `info` and `success` carry status. Charts are neutral: trend lines in the exercise charts and the body-weight chart use `chart-primary` (Ink on light, warm paper on dark), and the Profile week chart draws past weeks in `chart-secondary` with a `chart-secondary-edge` stroke and square bars, the current week in Amber.
- System is the default theme and follows live `prefers-color-scheme` changes. Light and Dark are explicit overrides. A validated, versioned `ember:appearance:v1` setting (`{version: 1, theme}`) is separate from workout data. Stored records from the former accent picker are still accepted: the accent is ignored and the theme kept, and the next write drops it. Denied appearance storage keeps the current tab usable and reports that the preference could not be saved; it never changes workout-saving claims.
- The HTML `theme-color` starts in Paper `#f6f1e8`; the inline head script (before first paint) and the appearance setting switch it to Paper or Night `#17161b`, which colours the status bar. The manifest `theme_color`/`background_color` are Night: installed Android apps fill the bottom gesture-bar strip and splash from the manifest alone, which cannot follow the theme, and a light strip under the dark app looked broken (owner chose Night). The app icon is the Ember heart: an amber heart whose right side rises into a flame, with a long shadow on a navy `#1F2D3D` tile, full-bleed in `public/icons` so maskable crops keep it.

## Typography

- Inter Variable is bundled locally via `@fontsource-variable/inter`, with Inter/system-ui/sans-serif fallbacks and `cv11`. No font CDN, display family or ornamental monospace is used.
- Named styles live in `src/index.css`: `page-title` 24px/600 with −.025em tracking, `section-title` 18px/600, `card-title` 16px/600, `label` 12px/500 and `caption` 11px. `set-value` is 18px/600 with tabular numerals (also `text-set-value`), `text-stat` is 28px/600 at −.02em for summary numbers, and the `numeric` utility sets tabular figures. Weights 550 and 650 are not used.
- Body copy (`p`) is 14px/1.5 in `muted-foreground`. `h1` is `page-title`, `h2` `section-title` and `h3` `card-title`; `h4` and tertiary headings are 16px/600, like exercise headings. Workout names are 18px/600, reducing to 16px below 350px.
- Set values are centered 18px/600, with tabular numerals. General inputs are 16px; button labels are 14px/500. Placeholders use `muted-foreground`. Supporting text is 12px (13px remains only in chart text), column labels, phone navigation labels and Previous dates 11px. Section labels (`.list-label`, `.session-sets-head`) are sentence case at 12/500; uppercase is kept only for compact metadata. Counts, source values and history tables use tabular numerals.

## Layout

- The workspace occupies `100dvh`, centered up to 1480px. Body scrolling is disabled; library, logger and dialogs have separate internal scroll regions.
- There is no top bar. Each tab's page title is an `h1` (the base `h1` rule, in the `page-title` style) at the top of the scroll content and scrolls away with it. A single `header.app-bar` holds the "Ember" brand, the Main navigation and a Settings icon button, and is laid out by viewport width:
  - **Phones (below 1000px):** it is a bottom tab bar with Profile / History / Workout / Exercises. The brand and Settings are hidden. Targets are 56px high; the bar adds a 1px top border and only the device's safe-area bottom inset. Labels are 11px/500. The active tab has a 2px Amber top rule and an Amber icon and label. It is hidden by visibility while an input is focused.
  - **Desktop (1000px and up):** it is a 48px header with a bottom border. "Ember" is 16/600, and the destinations are text-only links at 14/500 in `muted-foreground`. The active link uses `foreground` with a 2px Amber underline. Settings sits on the right.
- Below 1000px, the active logger is a full-screen sheet with a compact fixed name/Finish header, completed/total sets and elapsed time. A 2px Amber progress bar on the header's bottom rule fills (`scaleX`, 300ms strong ease-out) by the share of checked sets; that count and each exercise's "n / m sets" roll to their new value with NumberFlow (`RollingNumber`, `src/components/ui/rolling-number.tsx`). When the owner opens or minimizes it, the sheet slides up (420ms drawer curve) and down (300ms); a draft restored at launch is simply there, and the covered library hides only once the sheet has covered it. Save failures remain visible in the logger. The covered library is both inert and hidden from accessibility. The tab bar is unavailable until the workout is minimized.
- At 1000px and above, the logger is a 500px right column next to the interactive library. Desktop library padding is 26px 32px 40px. Templates use two columns without the logger and one column beside it; analytics stack within the narrower adjacent library.
- Mobile library padding is 24px 18px 30px. The named resume bar is at least 64px and participates in layout rather than covering records.
- Exercise sections use 20px 16px 18px padding (22px 24px in the desktop logger). Rows have **Set / Previous / kg (or Assist. kg/Seconds) / Reps (or km) / Done** columns: `44px minmax(66px,1fr) minmax(52px,.86fr) minmax(48px,.78fr) 48px`, 6px gaps and at least 56px row height. Below 350px, side padding is 12px and gaps 4px.
- Set-number/Previous actions and fields have at least 44px height; completion is 44×44px, right-aligned in its 48px column so it matches the fields' height, with a 30px visible outlined marker. Standard controls are at least 44px, appearance choices 48px. Five columns intentionally trade the former wide two-field mobile grid for per-set historical evidence.
- Portrait 390×844 and 320×740, short landscape 844×390, and desktop 1440×1000 are browser-tested. Focus/resize/visualViewport updates reveal inputs in the relevant internal scroller with 14px clearance. On phones the tab bar is hidden by visibility while an input is focused, preserving its layout space so blur cannot move a Save button between pointer down/up.

## Elevation & Depth

Flat surfaces, 1px borders and spacing establish hierarchy. The adjacent workout sheet has no shadow. Modal dialogs use `0 12px 48px #17161b26` in Paper and `0 12px 48px #0006` in Night above a scrim overlay: `scrim` (Night) at 60% on light and `252 12% 3%` at 85% on dark. Buttons use press feedback (`press-feedback`: colour, background and border over 160ms, and on touch screens a 0.97 scale while pressed). Whole-card buttons and `ActionSheet` rows use the prototype's `pressable` (a 0.985 scale while pressed, not while the card's own ⋯ is pressed). The overlay motion (`DialogContent`'s opt-in `motion`, used by `ResponsiveDialog`) fades the scrim and fades and zooms (95%) the centred dialog over 180ms on the strong ease-out; vaul drawers move on the 250ms drawer curve. Plain `Dialog`s (Settings, the History editor, the picker, exercise details) open and close without motion, because an exit keeps the closing scrim mounted for 180ms and would take a tap made right after closing; the logger's confirms, Previous evidence and ⋯ drawers use `ResponsiveDialog`/`ActionSheet`, and their tests wait for the scrim or drawer to leave. The motion tokens are `--ease-out` `cubic-bezier(0.23, 1, 0.32, 1)`, `--ease-in-out` `cubic-bezier(0.77, 0, 0.175, 1)` and `--ease-drawer` `cubic-bezier(0.32, 0.72, 0, 1)`. Reduced motion removes transitions, animations and smooth scrolling, except the finish celebration's fades. Selection, caret and scrollbar colors come from the active palette. Keyboard focus is a 2px `ring` outline (equal to `primary`) with a 2px offset, and −2px inside swipe rows and other controls that fill their container.

## Shapes

Buttons, inputs, panels and dialogs are square. Completed values lose field borders rather than becoming pills. Dialogs are normally at most 520px wide, within a 24px viewport gutter, height constrained and internally scrollable. Settings is a full-height right-hand modal panel on desktop (16px inset), full-screen below 1000px. Lucide supplies the existing icon vocabulary.

## Components

- **Library:** Four tabs are Profile / History / Workout / Exercises, initially Workout; they are the phone bottom tab bar and the desktop header links. Profile shows one muted line of totals with tabular numbers ("N workouts · N sets · N this week"; there are no stat tiles), then the last 12 weeks of workouts per week (average excluding the current partial week). On phones a 44px ghost cog (`aria-label="Settings"`) sits at the right of the Profile title, centred on the 32px title row without making it taller; it is hidden from 1000px, where the header gear is the entry. Workout has a sentence-case "Quick start" label with Start empty workout as its one primary button, then **Templates** (see Templates). History is described under History. Exercises combines the catalog with exact historical/custom names, search, body-part filters (only parts that hold at least one exercise, so Other appears only for names outside the catalog), recent rows and thumbnails; no recorded names are fuzzy-matched or merged. Each row ends with a bare count of the unique workouts that included it (an exercise repeated as separate blocks in one workout counts once): right-aligned, never shrunk, 16px/600 primary colour with tabular numerals, absent when never performed, and announced as "Performed in N workouts". Names wrap to at most two lines before truncating, so 3–4 digit counts don't squeeze them. A square two-segment **Most done / A–Z** toggle, Most done by default, (44px, `aria-pressed`) sorts the All list; Most done orders by that count, ties A–Z, never-performed last, and combines with search and body-part filters. The choice is a device preference in `ember:exercise-sort:v1`, separate from workout data. Recent stays by recency, and the shared Add exercise picker stays A–Z without the toggle.
- **ExerciseLine:** `src/components/exercise-line.tsx`, the one exercise row of History cards, template cards and previews, and the finish celebration: a 40px drawing tile, the name (14/500, two lines at most, breaking anywhere) over its body part (12px muted), and on the right in tabular numerals a bold 14/600 top line over a muted 12px second line. Finished work shows its **top set** (`topSet`: the heaviest weight with the most reps at it; an actual set, no formula) over the set count: "75 kg × 8", "12 reps" for bodyweight, "60 s" for holds, "1.2 km · 5:00" for cardio and "−20 kg × 8" for assistance, which screen readers hear as "20 kg assistance × 8" (`setText`/`performedLine` in `src/utils/set-label.ts`). An Amber 14px Trophy (named "Personal record") precedes the top set when the exercise set a record in that workout. Templates show the prescription Start will prefill (`plannedLine`): one load over its reps ("72.5 kg" over "3 × 8 reps", or "9 · 9 · 7 reps"); "Bodyweight" over the reps; varied loads show the top target set over the set count, so a load never sits next to reps it isn't paired with; blank targets show only the set count. The right column never wraps or shrinks; the name takes the remaining width. `Stat` in the same file is the icon-and-value pair of the card stat lines (14px icon, 12px muted tabular text).
- **History:** the title row carries a 44px ghost **Search history** button at the right (in `App.tsx`, outside the content fieldset, like the Profile cog); it toggles a search field (16px, a search glyph inside, focused on open) above the list, and closing it, Escape in the field or leaving the tab clears it. Search matches workout names, dates, month names and exercise names. Workouts are grouped by month: each month opens with a sticky label ("October 2026" in 12/500 `foreground`, the month's count of matching workouts at the right in muted tabular 12px) on a solid `background` that spans the scroller's full width and sticks flush with its top edge (a negative top equal to the scroller's top padding), so cards pass under it. Each card (`history-card`, a flat bordered `card`, 16px padding, 12px apart; two columns from 1000px, one beside the open logger) has a 36px weekday/day column (11px muted uppercase weekday over the 20px/600 day), the name in `card-title` (two lines at most) and a stat line of icon pairs: duration (omitted when unknown), volume in kg (recorded load × reps over weighted sets; omitted at 0) and, in Amber, the PR count when the workout set any (`recordsAt`: the records it set against only the workouts before it, so a record later beaten still shows). Under a hairline come up to five `ExerciseLine`s and "+ N more", indented under the name, or across the whole card below 350px so names keep room. The whole card is one button (an invisible full-card button named "<name>, <date>", described by the stat line, so the rows stay readable); it presses with `pressable` (scale .985, an `accent` wash on hover) and shows the focus ring on the card. 20 workouts show at first and **Show older workouts** adds 20 more. A just-finished workout keeps an Amber border (`focused-history`). No workouts shows "No workouts yet"; a search without matches shows "No matching workouts" with the query. A source link (Previous evidence, Charts, Records, exercise History) opens History with that workout's drawer open.
- **Workout drawer:** a `ResponsiveDialog` (`workout-drawer`): a bottom drawer below 1000px (at most the viewport less 40px), the centred dialog from 1000px. Its header holds the name, the full date and time ("Saturday, 31 October 2026 at 18:05"), and the stat line with the set count added; a 44px X closes it. The body scrolls: per exercise its drawing, name, record kinds in Amber (heaviest weight, most reps, session volume, then Est. 1RM (Epley)) and a set table (`recorded-sets`: Set, then Weight × reps, Assistance × reps, Reps, Time or Distance · time by type, and for weighted work an Est. 1RM column that shows "—" outside 1–10 reps), then the note "Est. 1RM uses the Epley formula and is shown for weighted sets of 1–10 reps." Closing it returns focus to the card; an action that opens something else hands focus to it. Edit, delete, their revision-conflict messages and the Android back gesture (the drawer and its menu each hold one back entry) are unchanged.

The dialog lives inside the logger, so it unmounts while sync is locked.

- **Settings entry points:** On phones, Settings opens from the cog beside the Profile title, which lives in `App.tsx` outside the disabled content fieldset so read-only and maintenance states can still open it; closing returns focus to it. The logger header gear and the locked-status gear cover the states where the tabs are unavailable. On desktop it is the header gear.

The resume bar is a `card` strip with a top border, a 3px Amber inset edge and an Amber chevron; the workout name is `foreground` at 600, and the time and sets are `muted-foreground`, led by a 6px Amber live dot with a soft ping (reduced motion stops the ping and keeps the dot). Weight Enter moves to reps; reps Enter explicitly completes only a valid unchecked set and blurs. Duration Enter validates/completes seconds; cardio moves seconds to distance. Bodyweight retains its noneditable load and editable reps. Numeric input modes, units and existing `validSet` bounds are preserved. Blank/invalid values cannot be completed or contribute to Finish.

Confirmation adds tint, a primary check and a colored index: the tint sweeps in from the check across the row (`clip-path`, 320ms; unticking wipes it out in 140ms), the 30px box pops (scale .86 → 1.08 → 1, 360ms) and its check path draws itself. When an exercise's last set is checked, its drawing gets a 20px Amber check badge and the heading flashes the tint once (900ms). Reduced motion keeps only the colour changes. Editing any numeric value clears completion. An exercise reads check + Done only when every nonempty set is valid and confirmed; adding/editing a set returns it to a count. Finish is disabled with no valid completed set. Disabled buttons are drawn at 0.5 opacity with their label kept. Cancel workout is a secondary (outline) button with destructive text; the destructive fill appears only on the confirming dialog button.
- **Targets:** Routine starts and exercise additions use the latest eligible actual matching name/type history, repeating its last available target for extra routine rows. No matching evidence means blank values. Repeating History copies that exact workout, not newer history. Every resulting draft is unchecked. Add exercise opens a full-screen picker shared with the Exercises library: search, body-part chips, Recent/All sections and thumbnail rows. Selecting a row adds it and closes the picker; Close or Escape leaves the draft untouched. Only existing catalog or recorded names can be selected; unmatched searches show No matching exercise, with no custom creation or type choice. Picking a name already in the workout keeps the picker open and shows "<name> is already in this workout." above the search, without changing the draft. Replacement checks the other cards, excluding the one being replaced. Existing imported repeated blocks are preserved. Template editing uses the same picker. Each exercise heading has a 44px ⋯ **Exercise options** menu with **Replace exercise** and **Remove exercise**, in the logger and the template editor. Below 1000px it is an `ActionSheet` bottom drawer titled with the exercise name: a `menu` of 56px rows with arrow/Home/End keys, focus on the first row, Escape, scrim tap and the back gesture closing it, and focus returning to ⋯ before the chosen action runs. From 1000px it is inline, not portaled, and opens below ⋯, flipping above it when there isn't room below. Escape or an outside tap closes it and focus returns to ⋯; a transparent backdrop takes that closing tap, so it never also completes a set or presses anything else. Tab closes it and continues from ⋯. Focus moving elsewhere closes it, so only one menu is open at a time. Remove drops the exercise immediately, without confirmation or undo, and focus moves to the next card's ⋯, else the previous card's, else Add exercise. Replace opens the same picker titled Replace exercise; the pick takes the same position with fresh history targets and the old sets, completed ones included, are discarded. Closing the picker changes nothing. Add set copies the last row unchecked. Routine editing uses targets-only rows and never records completed work.
- **Reorder exercises:** In the logger, the template editor and History editing, pressing and holding an exercise's heading (name, drawing or status; not ⋯) for 400ms lifts it, with a short vibration where supported. A tap opens details, and moving the finger first scrolls. While held, the heading sinks slightly (scale .97). Once lifted, every card is replaced by a compact list: one 56px row per exercise with thumbnail, name, completed/total sets (set count in editors) and a grip glyph. The logger scrolls so the held row sits under the finger, and it is drawn as lifted (surface fill, double accent border, shadow, scale 1.03; lighter fill in Night). The other rows slide aside by transform (220ms strong ease-out) as it crosses their centres, with a light tick per slot. Near the scroller's edges the list auto-scrolls. Release glides it into its slot (180ms), the full cards return with the dropped card's heading where the row was, and the card flashes the tint for 900ms. Escape, a cancelled pointer or leaving the window put it back unchanged. Scrolling is blocked only while an exercise is held. The move keeps the exercise's identity, sets, values and checks, and saves with the draft like any edit. Each ⋯ menu also offers **Move up** / **Move down** (only where possible), the keyboard and screen-reader path; focus stays on that exercise's ⋯ and a polite announcement gives the new position ("Moved X to position 3 of 5"), as it does after a drag. A list too short to scroll gets temporary space around it so the held row starts under the finger and every slot stays reachable. A release that lands just as the hold completes puts the exercise back; a drop while editing is locked does the same. A single exercise has nothing to reorder. Reduced motion drops the glide and tint.
- **Evidence:** Each Previous cell shows the latest matching session's actual set/date. Its dialog (a bottom drawer below 1000px, a centred dialog from 1000px) lists that session's exact sets and best reps at the selected row's exact entered weight with date/source workout. Assistance is explicitly labelled; duration/distance does not receive resistance estimates. No exact-weight history is stated plainly ("No sets at X kg"), followed by a **Nearest recorded** section: the best-reps actual set at the closest lighter and heavier recorded weights (Less/More assistance for assisted work), each with date and a source-workout button, worded as actual sets, never an inferred equivalent. Source navigation minimizes the logger and opens that workout's drawer in History.
- **Delete:** Native `pan-y` preserves scrolling. A left swipe from a non-input row area reveals Cancel/Delete; it never deletes or confirms by itself. Vertical intent, pointer cancellation/leave and post-swipe click suppression remain intact. Set-number actions provide explicit keyboard-accessible deletion: on phones the set number opens an `ActionSheet` with **Delete set**, from 1000px it reveals the row's Cancel/Delete. Deletion removes the selected set without an alert or undo banner, preserving remaining values, completion and order. Stable transient identity distinguishes duplicate exercise names and zero-set exercises.
- **Protected transitions:** Another routine, repeat or empty start requires an explicit replace-draft confirmation while a draft exists. Finish explains valid completed sets and excluded unchecked sets; saving delegates to the existing atomic finish transaction. A failed commit retains the draft, displays the storage error rather than a success claim, and permits retry. Only after the commit does the finish celebration open (see Finish celebration).
- **Finish celebration:** `src/components/FinishCelebration.tsx`, a full-screen Radix dialog on `background` (named "Workout complete") that opens over History once the finish transaction committed, with History already showing the new workout on top. Top to bottom: the lit Ember heart (the icon's heart-and-flame path in a `#FFC24B`→`#F2920A` gradient, scaling up from .82 with a slight overshoot over 700ms, a radial amber glow that swells over 1400ms and twelve sparks rising from the flame tip once), "Workout complete" in `page-title`, the workout name and weekday date, then a Duration / Sets / Volume row between hairlines (`text-stat` values counting up from 0 with NumberFlow over 900ms; a session under a minute reads "<1 min"; units wrap under the value when a column is too narrow). **New personal records** follow when the workout set any (`newRecords` in `src/domain/finish-summary.ts`, using the Records tab's `getRecords` definitions against every other workout: heaviest weight, session volume and Est. 1RM (Epley, 1–10 reps) for weighted work, most reps for bodyweight; none for assisted, duration or cardio work, a first session, a tie, or a kind with no earlier value). Each is one `card` row per exercise with a Trophy tile on `primary-tint`, the name, every record kind named in order (heaviest weight, most reps, session volume, then the estimate) and the headline record's value with its gain in `success`. Then **Exercises**: one `ExerciseLine` each, with a Trophy where a record was set. Content rises in a stagger (420ms, PR rows 180ms apart); `finish` plays on open and `pr` once per record row as it arrives. A pinned footer holds the one primary **Done** (focused on open; 320px wide from 1000px). Done, Escape and the back gesture close it (it holds one back entry) and focus moves to the new History card. Short landscape shrinks the heart. Reduced motion keeps the fades only: no sparks, glow growth or counting.
- **Body weight:** A `SettingsGroup` in Settings below Appearance. Its header carries the **Body weight** title and one line of context, with a 44px **Add weight** button in the group's action slot. The button opens an inline form in a `card`: a decimal kg field (comma or point, above 0 to 500, at most two decimals) and a `datetime-local` field prefilled with the current local time (below the kg field at 480px and narrower), then **Save entry** / **Cancel**, plus **Delete entry** when correcting. Enter submits; focus moves to kg on open and back to Add weight on close. Invalid input shows the existing inline error and saves nothing. With no entries the group shows a framed `EmptyState` ("No entries yet", with the Scale icon) and no chart card. With entries, a `card` headed **Weight (kg)** (an `h4`; its empty states are `h4` titles too) uses the exercise chart's approach (one SVG unit per CSS pixel via ResizeObserver, min/mid/max kg gridlines, first/last dates, time-spaced points, 11px labels verified in rendered CSS px at 412px) and always plots every live entry. With one entry the chart is replaced by an unframed `EmptyState` ("One entry so far") inside that card. Newest-first rows form a `SettingsList` (at least 64px, tabular numerals) showing date, time and kg with a chevron; each row is the edit button and its accessible name carries the exact values, so the list is the chart's exact-value alternative. Deleting shows an Undo notice. Disabled while read-only or in maintenance; unmounted while sync is locked.
- **Settings:** A modal panel of `SettingsGroup` sections, spaced 40px apart under the title: Appearance (System / Light / Dark only; the three 48px buttons sit directly under the header, the chosen one in a 2px Amber ring on a `card` ground), **Feedback** (a `SettingsList` of two 64px rows, Sounds and Haptics, each a full-row `role=switch` with an icon, the label, a one-line description and a 28×48px pill switch: on is an Amber track with a `background` knob, off a `muted` track with a `muted-foreground` outline and knob, which keeps it above 3:1), Body weight and, outside demo mode, **App update** (a `SettingsRow` with the **Apply shell update** action once a new shell is waiting). There is no import; the explicit PWA update path remains. Manual sync controls and the JSON Backup & Recovery panel are absent. Radix modal focus trapping/return, descriptions and close actions remain part of the modal design. Sync lock/read-only ownership does not disable opening Settings; protected body-weight/update paths retain their disabled-state gates. Untrusted owned workout data remains hidden. Notices and retained sync issues are readable in the modal, not trapped underneath it. Storage recovery APIs, validation/confirmation safeguards and server backup tools remain intact; they are not Settings features.
- **Feedback:** `src/feedback/` ports the prototype's cues: `start`, `set` (one step up a major pentatonic run per completed set), `unset`, `exercise`, `finish`, `pr`, `delete` and `tick`. Sounds are synthesised with Web Audio (no audio files) on an `ambient` audio session where supported, so music keeps playing and the iPhone silent switch is respected. Haptics use `navigator.vibrate` patterns on Android and the iOS 18 hidden `<input type=checkbox switch>` tick on iPhone (touch screens only). `cue()` never throws or blocks logging. The validated, versioned `ember:feedback:v1` setting (`{version: 1, sound, haptics}`, both on by default) is separate from workout data; a denied write keeps the choice for the tab and says so. Turning a switch on plays a tick. Starting a workout (empty, template or repeat, including after the replace-draft confirmation) plays `start`. An explicit check plays `set`, one step higher per set already checked in the workout; the exercise's last check adds `exercise` 160ms later; unticking plays `unset`. Removing a set or an exercise and discarding the workout play `delete`. The finish celebration plays `finish` when it opens and `pr` per record row; Done ticks. Opening a ⋯ menu, set actions or the Finish confirmation, `SegmentToggle` choices and `ActionSheet` rows tick; nothing cues on keystrokes or on completion cleared by an edit.
- **Durability:** Loading/saving/saved/error remain real workout-writer states, not appearance persistence or a delayed visual timer. Routine success status is not displayed as a permanent label; errors still surface. A saved state means the IndexedDB transaction committed. Storage errors remain visible inside the mobile logger; finish errors remain visible in its confirmation. Server synchronization runs silently in ordinary use and retains immutable pending-operation behavior. Authentication/ownership blocks and rejected sync operations still surface; routine connection/success states do not need a permanent card. Device saving and server sync are not off-device backup.
- **Analytics:** Weighted charts show best reps, best load, session volume and estimated 1RM; assisted charts show best reps and least assistance; bodyweight work has rep trends. Duration/distance-specific trends are not implemented. Best reps/load are not matched-weight/matched-rep comparisons: weights/reps can differ, so inspect the exact source sets. Records retain source links. Exact-value/source tables remain alternatives to charts. Epley estimates stay formula-labelled and bounded to appropriate weighted work. Bodyweight, assistance and duration/distance do not gain resistance formulas; recorded machine loads are not treated as equivalent across equipment changes.

## Implementation

- **Primitives:** `src/components/ui/button.tsx` (`Button`, cva variants `primary`, `secondary` (default), `ghost` and `danger`; sizes `normal` and `icon`) and `src/components/ui/input.tsx` (`Input`). Classes are merged with `cn` from `src/utils/cn.ts`, tailwind-merge 3 extended with the five named text sizes. `src/utils/plural.ts` holds the shared pluralisation helper.
- **Card:** `src/components/ui/card.tsx` (`Card`, and `cardClass` for elements that cannot be wrapped) is the flat bordered surface behind a block of content: `min-w-0 border border-border bg-card p-5`, square like everything else. `border-border` is explicit because Ember has no global border-colour default. The Profile week chart and totals, the template editor, the Body weight form and chart use it; `template-editor` stays a hook class (`template-editor` also sets `--row-bg`).
- **SettingsGroup:** `src/components/settings-group.tsx`. `SettingsGroup({id, title, titleAs?, description?, action?, children})` is a `section` labelled by its `text-card-title` heading (`h2` by default; Settings passes `h3` for its three groups, under the `h2` dialog title, and the headings nested in them, such as Weight (kg), are `h4`), with an optional `text-sm` muted description under the title. Ember adds `action`, a control on the title row, so a long description keeps the full width below it. `SettingsList` is `divide-y divide-border border border-border bg-card` (a `div` or `ul`). `SettingsRow({label, value?, action?})` is a `min-h-16` row; on phones it wraps, so a long label and value take the full width and the action drops below them. `settingsRowClass` is exported for rows that are themselves a button (the Body weight entries). The Profile Settings row uses the same list pattern.
- **Dialog:** `src/components/ui/dialog.tsx` holds thin wrappers over `@radix-ui/react-dialog`, styled with utilities; it is the one dialog system, also behind `ResponsiveDialog`. `DialogContent` takes a cva `variant`: `center` (confirms, Previous evidence, the workout drawer and the template preview from 1000px; up to 520px within a 24px gutter), `panel` (Settings and the History editor: full screen on phones, a 520px right-hand sheet from 1000px), `workout` (the logger's exercise details: the panel on phones, exactly the 500px workout column on desktop) and `fullscreen` (the exercise picker, content in a 900px column). It renders the portal and the `DialogOverlay` scrim (60% light, 85% dark). `DialogTitle` is an `h2` with no padding of its own; titles that share a row with a `DialogCornerClose` (Replace your active workout?, Finish this workout?, Previous evidence, the template preview) pass `pr-7`, and the others (the confirm titles without a close control, Settings, the picker, the History editor, the logger details heading) have none. `DialogDescription` is a 14px `p` under the title; `srOnly` hides it. `DialogActions` is the button row (right-aligned on desktop, stacked full width on phones, primary on top), `DialogClose` closes from an action and `DialogCornerClose` is the X at the top right of a centred dialog. The hook classes `dialog-overlay`, `dialog-content`, `settings-panel` and `exercise-detail-panel` stay on their elements: the visualViewport reveal and the tests select them. `DialogHeader` and `DialogFooter` (an alias of `DialogActions`) are the shadcn names, used by `ResponsiveDialog`.

Their `rounded-md`/`rounded-sm` resolve to Ember's 0 radius. `SegmentToggle` (`src/components/segment-toggle.tsx`, an outline single-choice ToggleGroup, the selected item on the `secondary` wash, 44px on touch screens) and `ActionSheet` (`src/components/action-sheet.tsx`, a drawer of full-width 56px action rows that the Android back gesture closes) are the prototype's. One sonner `Toaster` is mounted in `App.tsx`: top centre under the safe area on phones, bottom right from 1000px. The logger's Replace-draft, Discard and Finish confirmations, Previous evidence, the History workout drawer and its delete confirmation, the template preview and the template delete confirmation are `ResponsiveDialog`s (drawers on phones, primary action on top); exercise, workout, template and set ⋯ menus are `ActionSheet`s on phones. Existing notices stay as they are until a later change moves them.
- **Small shared pieces:** `ui/section-heading.tsx` (a title row with an action or caption), `ui/field-label.tsx`, `ui/content-fieldset.tsx` (the `content-fieldset` hook disables a block of content while editing is locked), `ui/inline-error.tsx` (a tinted error box; the caller sets the top margin) and `EmptyChart` in `ui/chart.tsx`.
- **Destructive confirm:** `danger` is a solid `bg-destructive text-destructive-foreground` fill, used only on confirming controls: Discard workout, Discard changes, History's delete-workout confirm and the template Confirm delete. Reset unreadable saved data (which opens a browser confirm), Body weight's undoable Delete entry and Cancel workout are secondary buttons with destructive text.
- **Mobile-native baseline (`@layer base`):** no tap highlight or text-size inflation, `overscroll-behavior: none` on the page and `overscroll-contain` on the library, logger and dialog scrollers; buttons, links, `role=button`, `role=tab` and `role=switch` take `touch-action: manipulation`, `user-select: none` and no iOS callout; inputs are at least 16px so iOS never zooms. Tailwind's `hover:` only applies on devices that hover, so hovers never stick after a tap.
- **Hook classes:** `Button` also emits `button`, `button-<variant>` and `button-icon`, and `Input` emits `input`. These and the structural names (`app-shell`, `workout-sheet`, `exercise-card`, `set-row`, `reorder-row`, `template-card`, `settings-panel` and similar) carry no styling of their own; tests and JS select them, so they stay on their elements.
- **Cascade:** `src/index.css` is the only stylesheet. It holds the tokens (including `--shadow`), `@layer base` (element globals: `:root` font and colour scheme, `body`, `::selection`, `::placeholder`, the `input` caret, reduced motion, the `*` scrollbar styling, `:focus-visible`, `h1`–`h4`, `p`, `button`, `a`), the `desk` breakpoint (1000px, giving `desk:` and `max-desk:`) and the custom variants `narrow` (≤350px), `short` (landscape, max-height 500px) and `logger-open` (`.workspace:has(.workout-sheet:not([hidden]))`). Every screen is styled with utilities, including the app shell (phone tab bar, desktop header, library scroller) and the banners (`noticeClass`, `errorBannerClass` in `src/components/banner.ts`): the Workout tab and logger, History (and its editor), Exercises, Templates, the exercise details with Charts and Records, Profile, the dialogs and Settings. Shared pieces live in `src/components/ui` and `src/components`: `EmptyState`, `Chip`/`ChipRow`, `ListLabel`, `ExerciseRow`, `data-table.tsx` (`dataTableClass`, `TextAction`) and `chart.tsx` (`trendChartClass`, `EmptyChart`, `MetricExplanation`); `trendChartClass` is shared by the exercise chart and the Body weight chart.
- **CSS that stays CSS:** `@layer components` in `src/index.css` keeps what utilities cannot express cleanly: swipe mechanics and `[data-commit]`, reorder `[data-held]`, `[data-dropping]` and `@starting-style`, exercise-card `[data-holding]` and `[data-dropped]` keyframes, and the `--row-bg` variable (set by `history-editor` and `template-editor`).
- **No overrides:** every rule is layered, so no `!` utilities are needed; add one only with a comment naming the rule it beats. The exceptions are library-injected styles, which are unlayered and so beat every layer: the vaul drawer timing rule at the end of `src/index.css` is unlayered for that reason, and `sonner.tsx` keeps its commented `!` utilities. `overlay-motion` sets tw-animate's `--tw-animation-duration`/`--tw-ease` instead of `animation-duration`, so it stays layered. The cascade order is preflight and `@layer base`, then `@layer components`, then utilities; the exceptions are the `!important` rules in `base` (reduced motion, preflight's `[hidden]`), which beat every later layer and must not be fought with a `!` utility. There is no global border-colour default, so every border names `border-border` (or another token).
- **Resume bar:** on hover it takes the `accent` wash and its meta line (time and sets) switches from `muted-foreground` to `foreground`, which keeps that line above 4.5:1.

## Do's and Don'ts

- **Do** keep the ledger primary, units explicit, values editable, checks intentional and historical evidence traceable.
- **Do** preserve one writer, immutable outbox payloads, security/ownership gates, retained source bytes and storage/recovery failures.
- **Do** use synthetic fixtures and local bundled assets for publishable examples.
- **Don't** copy approval-preview sample state/storage into the app, rewrite saved data for appearance, infer equivalent historical performances or claim saving before transaction commit.
- **Don't** call Chromium emulation native phone keyboard evidence, server sync off-device recovery, or this UI approval completion of the remaining release gates. Real-device acceptance and disaster-recovery rehearsal remain separate gates; existing encrypted off-device backups are not a UI saving claim.
